Опыт 10. Адаптация к узкому экрану

Медиазапрос «не более 48 rem» отключён: действуют только широкоэкранные правила.

Что меняем

Исходное значение: @media (max-width: 48rem) { .layout, .cards { grid-template-columns: 1fr } .menu { flex-direction: column } .story-image { float: none } .site-header { position: static } }

Изменённое значение, файл exp10.css: те же широкоэкранные объявления загружены без медиазапроса и отменяют его правила

Как смотреть

  1. Откройте стенд на ширине 1200 CSS-пикселей — он выглядит так же, как сайт.
  2. Сузьте окно до 768 px: на сайте в этот момент появляется одна колонка, а здесь остаются две.
  3. Сузьте окно до 375 px и включите масштаб 200 %: текст заметки сжимается в узкую колонку, а внизу страницы появляется горизонтальная прокрутка.
  4. Сравните с настоящим сайтом index.html, где медиазапрос работает.

Видимый результат

На 768 px колонки сетки остаются в отношении 2:1, меню продолжает лежать в ряд, фотография продолжает обтекаться текстом, шапка остаётся закреплённой. Читать неудобно: строки текста в заметке и в карточках укорачиваются, длинные пункты меню сжимаются, но горизонтальной прокрутки ещё нет.

На 375 px начинается переполнение. Колонка карточек сжимается примерно до 88 px, под заголовок остаётся около 56 px, и длинные слова перестают помещаться: ширина страницы становится 432 px при ширине окна 360 px, то есть появляется горизонтальная прокрутка всей страницы. Объявление minmax(0, ...) разрешает колонке сжиматься, но не может сделать слово короче — поэтому на самом узком экране медиазапрос необходим.

Объяснение и исправление

Адаптация строится в два шага: сначала задаются гибкие размеры, затем через медиазапрос меняется раскладка, когда содержимому становится тесно. Порог выбирают по поведению страницы: при начальном шрифте 16 px значение 48 rem соответствует 768 px. Отключение медиазапроса показывает, какие правила он отменяет: на 768 px страница остаётся читаемой, а на 375 px появляется переполнение по горизонтали. Исправление — вернуть медиазапрос: на узком экране нужна одна колонка, меню-колонка, возврат фотографии в поток и обычная шапка.

Стенд: меню и обтекание

На узком экране фотография продолжает обтекаться текстом, поэтому строки становятся очень короткими. Так выглядит заметка без правила float: none из медиазапроса.

Абзац с классом after-image по-прежнему переносится под фотографию: правило clear: both медиазапросом не отменяется.
